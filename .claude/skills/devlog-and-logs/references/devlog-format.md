# 개발일지 양식

규칙 원문은 `CLAUDE.md` §1이 소유한다. 이 파일은 양식과 예시만 담는다.

제목의 **한국시간은 필수**다 — 하루에 항목이 여러 개 쌓이면 날짜만으로는 순서를 알 수 없다
(2026-09-06 실측: 하루 17개). `scripts/check-devlog-update.mjs` 가 커밋 때 이걸 강제한다.

```markdown
## YYYY-MM-DD (요일) HH:MM KST — <한 줄 제목>

- **증상**: 무엇이 잘못 보였나 (사용자 표현 그대로)
- **원인**: 파일:줄 + 왜 그렇게 되는지
- **조치**: 바꾼 파일과 한 줄 요약
- **측정**: 전/후 수치 + 실행 id (없으면 "측정 안 함"이라고 적는다)
- **남은 것**: 안 고친 것과 그 이유
```

## 잘 쓴 항목의 조건

- **수치는 실측만.** 지어낸 숫자는 이 체계를 통째로 무용지물로 만든다.
  실행 id(`0811-171221-after-guards`)를 함께 남겨 나중에 같은 로그로 재확인할 수 있게 한다.
- **반증된 것도 남긴다.** 외부 지적이 이미 구현된 기능을 가리키는 경우가 잦다
  (2026-08-11에 9개 중 3개가 그랬다).
- **내가 세운 가정이 뒤집혔으면 그 가정을 적는다.** 예: 2026-08-19 블라스트 가드 —
  "위험하면 확인 관문을 추가한다"고 설계했는데 쓰기 액션은 **이미 전부 CONFIRM**이었다.
  사고 원인은 관문 부재가 아니라 카드가 "B10을 수정합니다"라고만 한 것이었다.
  이 한 줄이 다음 사람의 반나절을 아낀다.
- **날짜는 절대 표기로.** "어제", "지난주" 금지.

## 측정 안 한 경우

숨기지 말고 그대로 적는다:

```markdown
- **측정**: 측정 안 함 — 배터리가 돌고 있어 동시 실행을 피했다. 다음 회차에 포함.
```

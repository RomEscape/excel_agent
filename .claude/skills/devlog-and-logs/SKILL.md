# 진단은 로그부터, 마무리는 개발일지

증상만 보고 코드를 뒤지면 원인이 모델의 변덕일 때 끝없이 헤맨다. **판단 경로를 먼저 본다.**

## 1. 어디서 갈렸는지부터 — 추측 금지

배터리 실패면 이것 하나로 시작한다. 러너 로그와 `logs/chat_log.jsonl`을 턴별로 합쳐
실패마다 **경로 · 훅 · 모델 계획 · 검증 오류**를 보여 준다.

```powershell
$PY = "$env:LOCALAPPDATA\officeclaw\venvs\python-sidecar\Scripts\python.exe"
& $PY python-sidecar\scripts\dialogue_failures.py <dialogue_exN_log.json> [...]
```

로그에서 무엇을 읽는지, 한 턴을 더 깊게 보는 법은 → [references/log-reading.md](references/log-reading.md)

**가장 중요한 한 줄**: `routes[].at`이 `quick_rule:hit`이면 **그 턴에 LLM은 호출되지도 않았다.**
프롬프트·모델을 아무리 고쳐도 그 경로는 안 바뀐다.

## 2. 응답을 믿지 말고 파일을 연다

사이드카는 **계획대로 실행됐으면 성공으로 보고한다 — 계획이 틀렸어도.**
2026-08-19 실측: 배터리가 99.7%라고 한 상태에서 결과 워크북에는 명령문이 박힌 칸 4개,
원본 시트에 잘못 쓰인 수식 6건, **지워진 학생 이름 1개**가 있었다.

```powershell
& $PY <scratchpad>\scan_command_text_cells.py   # 셀에 명령문이 박혔는지 전수 검사
```

## 3. 고쳤으면 재고 나서 고쳤다고 한다

한 번 본 실패로 코드를 고치기 시작하면 원인이 모델의 변덕일 때 헤맨다.
before/after를 재고, 일반화는 **블라인드 게이트**로 잰다 — 회귀 배터리는 일반화를 증명하지 못한다.
보는 지표는 정답률보다 **조용한 오실행률**이 먼저다.

명령어 전수 → [references/measuring.md](references/measuring.md)

## 4. 개발일지 — 코드를 고쳤으면 예외 없이

규칙 원문은 `CLAUDE.md` §1이 소유한다. 여기서는 **빠뜨리기 쉬운 것만**:

- [ ] 증상은 **사용자 표현 그대로**
- [ ] 원인은 **파일:줄 + 왜**
- [ ] 측정은 **실측 수치 + 실행 id** (안 쟀으면 "측정 안 함"이라고 적는다)
- [ ] **내가 세운 가정이 뒤집혔다면 그 가정과 무엇이 뒤집었는지** — 다음 사람을 가장 많이 아끼는 항목
- [ ] 날짜는 절대 표기("어제" 금지)
- [ ] 커밋 메시지에도 같은 수치를

양식과 예시 → [references/devlog-format.md](references/devlog-format.md)

> `lefthook`의 `devlog-guard`가 커밋을 막아 준다. 다만 훅은 **파일이 바뀌었는지**만 본다 —
> 내용이 실측인지는 사람만 안다.

## 5. 배터리 운영 — 오늘 두 번 겪은 것

- **동시 실행 금지.** 같은 워크북·사이드카를 두 배터리가 만지면 결과가 섞인다.
- **배터리가 도는 중 패키지 파일을 고치지 않는다.** `run_dialogue.py`는 각본마다 새 프로세스로
  임포트해서, 중간에 파일이 깨져 있으면 그 뒤 각본이 **전부 0턴**이 된다. 테스트·문서는 괜찮다.
  (게이트는 단일 프로세스라 시작 후 편집은 안전하지만, 결과는 시작 시점 코드를 반영한다.)
- v1/v2 각본은 **같은 워크북을 공유**한다. 결과 대조는 마지막에 돈 각본 기준으로.
- `dialogue_failures.py`가 없으면 러너 로그와 `chat_log.jsonl`을 직접 맞춰야 한다 —
  먼저 `python-sidecar/scripts/`에 있는지 본다.

## 6. 도구 함정 — 조용히 소스를 망가뜨리는 것들

- **heredoc은 `\`를 삼킨다.** `sh <<'EOF'`로 정규식을 패치하면 `\b`가 파일에
  **백스페이스 문자(0x08)로 박힌다.** ruff도 import도 통과해서 안 보인다.
  정규식·이스케이프가 든 패치는 **파일로 쓴 뒤 실행**한다(2026-08-20 실측).
  의심되면: `python -c "print([i+1 for i,l in enumerate(open(F,encoding='utf-8')) if chr(8) in l])"`
- **새 검증 층은 실패만 추가할 수 있다.** 통과/해당없음이면 `None`을 돌려준다.
  `(True, "")`를 돌려주면 **기존 검사를 덮어써서** 원래 잡히던 실패가 통과된다(2026-08-19 실측).
- **한글에는 낱말 경계가 없다.** 정규식 `\b`는 한글·한글 사이에 경계를 만들지 않아
  `적어(?:줘)?\b`가 `적어주세요`에서 실패한다. 끝은 `(?=[\s,.!?~…]|$)`로 잡는다.

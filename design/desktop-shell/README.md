# 데스크톱 셸 — 최종 채택 와이어프레임 스펙

## 왜 이 문서가 생겼나

PR #27에서 제가(@Jxxhwan) 올린 `DesktopAppShell.jsx`(`8a6513e`)는 **최종 채택안이 아니었습니다.**
디자이너가 만든 여러 와이어프레임 중 채택하지 않은 쪽을 제가 착각해서 내보냈습니다.
PR #28이 그 파일을 디자인 스펙으로 삼아 구현됐으므로, 현재 `dev`의 UI는 **채택되지 않은 안을 따르고 있습니다.**

이 PR은 코드를 바꾸지 않습니다. **최종안을 기계적으로 추출한 스펙 문서만** 추가합니다.

- [`SCREENS.md`](SCREENS.md) — 14개 화면 상세 (Figma 딥링크 포함)
- [`TOKENS.md`](TOKENS.md) — 라이트/다크 색 토큰
- [`raw/light/`](raw/light) · [`raw/dark/`](raw/dark) — Figma REST API로 뽑은 노드 트리 원본 (텍스트·크기·fill)

지난번처럼 절대좌표 JSX 덩어리를 올리지 않았습니다. 그건 그대로 쓸 수 없다는 걸 PR #28에서 확인했습니다.
`apps/` 밖에 두었으므로 빌드·린트 대상이 아니고, 브랜드 색 규칙에도 걸리지 않습니다.

**출처:** Figma `김대리_기획안` — 라이트 `Frame 159~172`, 다크 `Frame 145~158`.
이번엔 프레임 번호와 노드 ID를 전부 명시했으니 대조해서 확인해 주세요.

## 구버전(`8a6513e`) 대비 무엇이 달라졌나

구버전은 7570px 캔버스에 5개 화면이었습니다. 신규안은 **14개 화면 × 라이트/다크 2벌 = 28프레임**입니다.

### 1. 온보딩 7화면이 통째로 추가됐다 — 가장 큰 변화

구버전에는 설치 흐름이 아예 없었습니다. 신규안은 3단계 위저드가 있습니다:

`파일 설치` → `모델 설치` → `워크스페이스 지정`

진행 바, 파일 체크리스트, AI 모델 셀렉트(Opus 4.0 / Deepseek / Gemma 3.0·4.0 / KIMI), 폴더 선택,
CTA 활성·비활성 상태까지 그려져 있습니다.

**좋은 소식:** 이 기능들의 코드는 이미 저장소에 있습니다.

| 화면 | 기존 파일 |
|---|---|
| 설치 진행 | `components/onboarding/OnboardingWizard.jsx`, `components/guide/SetupGuide.jsx` |
| 모델 선택 | `components/settings/OllamaModelPicker.jsx`, `components/guide/LocalAISetupWizard.jsx`, `lib/localAISetup*.js` |
| 워크스페이스 지정 | `components/workspace/WorkspacePage.jsx` (폴더 선택 경로) |

즉 **없는 기능을 새로 만드는 게 아니라, 이미 있는 화면에 디자인을 입히는 작업**으로 보입니다.
다만 저는 이 파일들의 실제 커버 범위를 읽어보지 않았습니다 — 실제로 얼마나 맞아떨어지는지는 확인 부탁드립니다.

### 2. 다크모드가 추가됐다

14화면 전부 다크 쌍이 있습니다. 노드 트리를 1:1 비교한 결과 **구조는 동일하고 색만 다릅니다.**
레이아웃 재작업이 아니라 토큰 작업입니다. 자세한 건 [`TOKENS.md`](TOKENS.md).

`index.css`는 현재 `:root {}` 하나뿐이고 `.dark {}`가 없습니다.
다만 다크 지면색 `#0C1909`은 이미 `--sidebar-background: 109 47% 7%`로 코드에 있습니다.

### 3. 홈 화면이 상태 카드 → 문서 그리드로 바뀌었다

| | 구버전 (현재 구현됨) | 신규안 |
|---|---|---|
| 시작 화면 | 인사말 + 상태 카드 3장(보안 상태 / 최근 분석 데이터 / 예정된 자동화) + `새 업무 시작하기` CTA | 인사말 + **문서 카드 그리드** + 문서 액션 바(`새로운 문서 생성` / `문서 업로드` / `문서 삭제`) + `15개 문서 더보기...` |

현재 `ChatPage`의 빈 상태(상태 카드 3장)가 이 자리입니다. 신규안에선 그 자리가 문서 관리 지면이 됩니다.

### 4. 채팅이 페이지가 아니라 "떠 있는 패널"이 됐다

신규안에서 채팅은 390px 폭 패널이고, 크기가 **2단 이상 변합니다** (390×507 플로팅 ↔ 390×900 전체 높이).
패널 상단의 `tabler:aspect-ratio` 아이콘이 그 토글입니다. 본문 지면(엑셀/문서)은 그 옆에 남습니다.

> PR #28에서 `WorkspacePage`의 `ChatSidePanel`(약 600줄)을 걷어내고 채팅을 독립 페이지로 만드셨는데,
> **신규안은 오히려 그 사이드 패널 구조에 가깝습니다.** 되돌릴 부분이 있는지 확인이 필요합니다.
> 여기가 이번 건에서 가장 비싼 지점으로 보입니다 — 판단 부탁드립니다.

### 5. 채팅 UI에 신규 요소 3개

- **말풍선 액션 행** — 사용자: 되돌리기·편집·복사 / AI: 되돌리기·복사, + 타임스탬프
- **툴 진행 스텝 칩** — `문서 형식 파악 완료` → `데이터 처리 완료`
- **스켈레톤 로딩** — `새로운 시트 제작중...` + shimmer 바

그리고 **CONFIRM 승인이 모달이 아니라 말풍선 인라인 버튼**(`네 Y` / `아니오 N`)입니다.
현재는 `components/security/ApprovalDialog.jsx` 모달입니다.

### 6. 사이드바 구성이 다르다

| | 현재 (`ConversationSidebar.jsx`) | 신규안 |
|---|---|---|
| 내비 | 채팅 · 대시보드 · 워크스페이스 · 대화 모니터링 · 설정 (푸터) | 대시보드 · 워크스페이스 · **작업 검색**(확장) · **대화목록**(확장) |
| 푸터 | 설정 | **도움말** · 환경 설정 |
| 지면 | 라이트 모드에서도 다크 | 테마를 따라감 |
| 대화 목록 | 상시 노출 (오늘/어제/지난 7일) | chevron 확장형 내비 항목 |

- `작업 검색`은 현재 `cmdk/CommandPalette.jsx`(단축키)로만 있고 내비 항목이 아닙니다.
- `도움말`은 현재 내비에 없습니다 (`cmdk/ShortcutHelp.jsx`는 있음).
- 신규안 내비에 `채팅` 항목이 없습니다 — 홈이 곧 진입점이기 때문으로 읽힙니다.

### 7. QR 페어링에 TTL·스토어 배지가 붙었다

`components/relay/RelayPairing.jsx`가 이미 있습니다. 신규안이 추가한 것:
**남은 시간 카운트다운(`3:29`) + 재발급 버튼 + Google Play / App Store 배지.**
PR #25에서 페어링 code에 TTL을 넣으셨으니, 그 값을 그대로 노출하면 될 것 같습니다.

## 살릴 것 / 고칠 것 / 새로 할 것

이번 변경은 **표현 계층**입니다. PR #28에서 만드신 순수 모듈은 와이어프레임과 무관합니다.

### 그대로 살아야 하는 것 (건드릴 이유 없음)

- `lib/excelResult.js` · `lib/chatSessions.js` · `lib/excelRangeContext.js` — 순수 모듈 + 테스트 58개

- `formatExcelLiveResult()`가 `read_range`의 `values`를 버리던 버그 수정 — UI가 바뀌어도 유지돼야 합니다
- `summary` 필드 유지 (세션 영속화·메신저 전송이 의존)

### 표현만 바뀌는 것

- `ui/chat.jsx` — 말풍선에 액션 행·타임스탬프 추가, 색을 `#2DB400`/`#E1E6DF` 대응 토큰으로
- `layout/ConversationSidebar.jsx` — 내비 구성 변경, 지면 토큰화
- `chat/ChatPage.jsx` — 빈 상태를 문서 그리드로
- `layout/Layout.jsx` — 채팅 패널 도킹/플로팅 구조

### 새로 필요한 것

- `index.css`에 `.dark {}` 블록 + 테마 토글
- 채팅 패널 크기 토글 (`aspect-ratio`)
- 툴 진행 스텝 칩 · 스켈레톤 로딩
- 인라인 CONFIRM 버튼 (모달 → 말풍선)
- 문서 카드 그리드 + 문서 CRUD 액션 바
- 온보딩 3단계에 디자인 적용

## PR #28에 남기신 질문 3개 — 답변

늦어서 죄송합니다. 신규 와이어프레임 기준으로 답합니다.

**1. 사이드바 푸터 내비게이션**
판단이 맞았습니다. 신규안도 사이드바에 내비를 두고 있습니다. 다만 구성이 다릅니다 —
상단에 `대시보드 · 워크스페이스 · 작업 검색 · 대화목록`, 푸터에 `도움말 · 환경 설정`.
신규안 내비에는 `채팅` 항목이 없는데, 홈 화면 자체가 채팅 진입점이라 그런 것으로 읽힙니다.
말씀하신 "보던 대화로 돌아올 경로" 문제는 신규안에서도 그대로 남으니, 구현하실 때 유지 부탁드립니다.

**2. `lime-*` → 테마 토큰**
전적으로 맞습니다. 최종안의 실제 브랜드 값은 `#2DB400`이고, `index.css`에 이미 있는 그 값입니다.
`lime-*`은 제가 잘못 내보낸 파일의 Figma 근사치였습니다. 토큰 유지해 주세요.
다만 다크 팔레트가 새로 필요해서 [`TOKENS.md`](TOKENS.md)에 정리했습니다.

**3. `● ● ● 김대리 AI` 타이틀바**
**장식이 맞습니다.** 최종안 28개 프레임 어디에도 그 요소가 없습니다. 옮기지 않으신 게 맞습니다.

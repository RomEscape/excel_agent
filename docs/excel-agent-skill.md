# Excel 에이전트 스킬 — 작업 중인 파일을 읽고 이어갈 일을 판단한다

이 문서는 **사람이 읽는 명세이자, 프롬프트에 주입되는 본문**이다.
`services/sidecar/scripts/apply_agent_skill.py` 가 이 파일의 `## 주입 본문` 절만 떼어
학습 상태의 `active_prompt` 로 넣는다 — 그러면 플래너 프롬프트의 `추가 지침` 슬롯에 실린다.

내용은 **지어내지 않았다.** 전부 2026-09-07~08 실측에서 실제로 데이터를 망가뜨렸거나
사용자를 헛돌게 한 사례에서 뽑았다. 근거를 항목마다 적어 둔다.

## 왜 이 스킬이 필요한가

이 저장소의 코퍼스는 오랫동안 **붙여넣기로만** 시작했다. 붙여넣기는 프런트가 범위 문맥
(`lastExcelRangeRef`)을 함께 준다. 그런데 실사용에서 가장 흔한 형태는 **사람이 Excel에
직접 타자해 둔 상태**이고, 거기엔 그 문맥이 없다. 규칙과 가드가 "문맥이 있다"는 전제 위에
서 있어서, 그 전제가 무너지는 축을 재자마자 데이터 파괴가 나왔다(2026-09-08 시드 배터리).

## 주입 본문

작업 중인 통합문서를 먼저 **읽고 진단한 뒤** 이어갈 일을 정한다. 아래는 그 판단 규칙이다.

1. **이어 쓰기는 빈 행부터.** 통합문서 상태의 `빈행=N부터`가 이어 붙일 자리다.
   "이어서·추가로·나머지도·계속" 같은 말이 있으면 **절대 1행부터 쓰지 않는다** —
   사람이 친 머리글과 기존 행이 사라진다.
2. **사람이 이미 채운 칸은 덮지 않는다.** 사용범위 안의 값을 지우거나 덮어야 한다면
   그건 실행이 아니라 확인 대상이다. 새 열이 필요하면 `빈열=`부터 쓴다.
3. **말하지 않은 값을 지어내지 않는다.** "나머지도 채워줘"처럼 무엇을 넣을지 없는
   문장은 되묻는다. `나머지·전부·그거·이것` 같은 지시어를 **값으로 쓰지 않는다**.
4. **머리글은 데이터가 아니다.** 표의 첫 행은 열 이름이다. 정렬·집계·필터는 머리글을
   제외한 데이터 행에만 적용한다.
5. **되돌릴 수 없는 일은 대상을 확인하고 한다.** 열 삭제·행 제거·중복 제거는 어느 열,
   어느 조건인지 문장에 없으면 되묻는다. "필요 없는 열"이 무엇인지는 사람만 안다.
6. **부분 보류를 전면 보류로 읽지 않는다.** "결석 열 비우고 나머지는 그대로 둬"는
   결석 열을 비우라는 뜻이다. 반대로 "지금은 아무것도 하지 마"는 아무것도 하지 않는다.
7. **사정과 요청을 가른다.** "예전엔 매크로로 뽑았는데" "PDF는 제가 할게요"처럼 배경으로
   언급된 것은 실행 대상이 아니다. 실제 요청 문장만 실행한다.

## 재 봤다 — 그리고 **제품에 넣지 않는다** (2026-09-08)

> 이 절을 읽지 않고 주입을 켜지 마라. 한 번 잰 것을 다시 재게 하지 않으려고 남긴다.

같은 코드·각본·모델로 53턴(시드 45 + macro 8)을 **주입한 것과 안 한 것**으로 나눠 돌렸다.

| | 스킬 없이 | 스킬 넣고 |
|---|---|---|
| 점수 | 49/53 | 49/53 |
| 실질이 다른 턴 | — | **6턴** |
| 유리하게 바뀐 턴 | — | **0건** |

점수는 동률이지만 **행동은 바뀌었고, 확인된 방향은 나빴다.** 독립적으로 갈린 것은 둘이다
(나머지 4턴은 아래 첫 건에서 어긋난 범위가 뒤로 이월된 것):

- `seedC t9` "머리글 행에 배경색 넣고 굵게" — 넣지 않으면 `planner:local` 성공,
  **넣으면 `planner:failed`**. 플래너가 없는 액션 `excel_live.set_background_color` 를
  지어냈다(프롬프트 6923자 → 7651자). 폴백이 대신 칠해 **A1 1칸 → G1:G8 8칸**.
- `seedE t6` "다른 시트로 옮겨줘" — 되묻기가 "어떤 시트를 **어디로** 옮길까요?" →
  "어디로 옮길까요?" 로 줄었다. 물어야 할 것을 덜 물었다.

### 왜 안 통했는지 — 구조적 이유 셋

1. **플래너가 이 슬롯을 학습한 적이 없다.** 학습셋에서 `추가 지침(Persona memory)` 0건,
   통합문서 상태 블록의 `열:`·`예시행` 도 0건이다.
2. **슬롯이 존재하는 턴 자체가 적다.** 53턴 중 실제로 플래너를 부른 것은 12턴뿐이다.
   나머지는 빠른 규칙이 확정하거나 **의도 정규화**(`excel_intent_normalizer`)가 처리하는데,
   정규화는 자체 프롬프트를 쓰고 거기엔 개인화 지침이 들어갈 자리가 **없다**.
   경로 이름 `planner:local` 은 플래너 호출을 뜻하지 않으니 그걸로 도달률을 세면 안 된다
   (`llm_call purpose=planner` 로 세야 한다).
3. **이 코퍼스로는 애초에 답이 안 나온다.** 기준이 49/53(92.5%)로 포화라 실패가 4건뿐이고,
   짝지은 부호검정 상한이 4라 **스킬이 4건을 전부 고쳐도** 단측 p=0.0625 다.

### 그래서 어떻게 다루나

- **주입은 켜지 않는다.** 실험 뒤 걷어냈다(`active_prompt` 전부 0자).
- **하네스와 이 문서는 지우지 않는다.** `scripts/apply_agent_skill.py`(심기·걷기),
  `scripts/run_skill_ab.py`(두 조건 비교), `scripts/probe_planner_prompt.py`(실제로 모델에
  간 문자열 받아 적기) 가 재현 수단이다.
- **다시 재려면 순서가 있다.** 지금 채점은 같은 명령에 1칸을 칠하든 8칸을 칠하든 `ok` 다.
  그 눈금으로는 무엇을 바꿔도 판정이 안 된다. **채점을 실제로 건드린 셀 범위로 바꾼 뒤**,
  스킬 규칙이 겨냥하는 실패 유형으로 코퍼스를 다시 짜고, `llm_call purpose=planner` 가
  있는 턴만 분모로 삼아야 한다.

### 내용 자체가 틀린 것은 아니다

위 7개 규칙은 전부 실제로 데이터를 망가뜨린 사례에서 뽑았고, 상당수는 이미 **규칙 층에
코드로** 들어가 작동 중이다(이어 쓰기 위치·블라스트 반경·지시어를 값으로 쓰지 않기 —
시드 배터리를 37/45 → 41/45 로 올린 그 변경들이다). 안 통한 것은 지식이 아니라
**그 지식을 플래너 프롬프트 슬롯에 텍스트로 넣는 방식**이다.
